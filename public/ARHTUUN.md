## What Arh'tuun does for this app

This app can produce **Continuity Anchors** at meaningful moments — not on
every edit. Each anchor captures four things:

- **Vector** — where this project is trying to go (the desired future state,
  not the task).
- **Weight** — why it matters right now.
- **Open Loop** — the specific unresolved question / next action.
- **Pressure** — the nature of the work (`creative_flow`, `urgent_solving`,
  `analytical_thinking`, `routine_execution`).

Anchors are **append-only** and, when a Kaspa wallet is connected,
**cryptographically anchored** to the Kaspa ledger. Anchoring stores only a
**hash** on-chain — never source code, secrets, or user data.

---

## What belongs on-chain (and what never does)

**Anchored (hash only):** the Continuity Anchor, the project manifest hash,
Git commit SHA, deployment identifier, selected public metadata.

**Never on-chain:** API keys, private keys, passwords, credentials, LLM keys,
seed phrases, wallet secrets, user PII, source code content, full file
bodies.

If you are unsure whether something is safe to anchor — **don't.** Hash the
public manifest and stop there.

## Sources of truth

This app treats these as **distinct**, never one merged state:

| Layer      | Owns                          |
|------------|-------------------------------|
| Filesystem | what files exist now          |
| Git        | what was committed            |
| Deployment | what is live at a URL         |
| Kaspa      | what was cryptographically asserted + when |
| Arh'tuun   | what was intended, and why    |

If they disagree, Arh'tuun surfaces the divergence — it does not silently
pick one.

## Using continuity (local, no wallet required)

Without a Kaspa wallet, this app still keeps continuity:

- Anchors are stored locally with the project (this file + a local anchor
  store).
- On return, the app can regenerate a **Return Thread** — a compact summary
  of where the project is, where it's going, what's unresolved — without
  replaying full history.
- The LLM context is treated as a scratchpad, not as the project's memory.

## Verifying continuity (opt-in, wallet required)

With a Kaspa wallet connected, anchors are hashed and the hash is anchored
on-chain:

- Each anchor records a `kaspa_tx_hash` + `block_height`.
- Anyone — including a cloned instance of TTT Builder — can recompute the
  canonical hash and verify it against the on-chain transaction.
- This makes the project's continuity **tamper-evident** and
  **time-sequenced**, without trusting any single host.

On-chain anchoring is **optional.** Local-only mode keeps full continuity;
it only loses cryptographic verification.

## Portability

This file is **portable and user-owned.**

- Export = files + Git ref + deployment ref + this anchor log + (optionally)
  anchored tx hashes.
- Import on any TTT Builder instance (hosted or self-hosted) reconstructs the
  full continuity.
- The schema is model-agnostic: a different LLM, a different config, a
  different machine can all read the same anchor chain.
